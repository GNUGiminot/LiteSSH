# История изменений

## 1.1.13 — 2026-11-17

### Сетевой экран (VPSWall)

- «Установить с GitHub» ставит **последний выпуск** VPSWall (сейчас [0.4.0](https://github.com/GNUGiminot/vpswall/releases/tag/v0.4.0)) вместо вшитого 0.3.0: новая версия VPSWall больше не требует выпуска LiteSSH. Архив `vpswall-<версия>.zip` сверяется по SHA-256 из `SHA256SUMS.txt` того же выпуска; файлы скачиваются только из `github.com/GNUGiminot/vpswall/releases/download/`. После установки показывается установленная версия.

## 1.1.11 — 2026-11-17

### Темы интерфейса

- «Настройки» → «Тема интерфейса»: кроме стандартной светлой/тёмной — 8 палитр: Пергамент, Мёд, Терракота, Шалфей, Чертёж, Сумерки (светлые), Мастерская, Ночная смена (тёмные). Палитра задаёт фон, карточки, линии, текст и акцент; светлый или тёмный режим (редактор кода, титлбар) берётся из неё, поэтому кнопка «солнце/луна» в шапке скрыта, а свой акцентный цвет недоступен, пока выбрана палитра. Тема терминала не меняется — выбирается отдельно.
- Текст на акцентных кнопках берётся из палитры: у тёмных тем акцент светлый и белый текст на нём не читался.

### Сетевой экран (VPSWall)

- Кнопка «Сетевой экран» (щит) у SSH-вкладки: LiteSSH сам не правит firewall, а встраивает [VPSWall](https://github.com/GNUGiminot/vpswall) сервера. Проверяет, установлен ли он; если нет — по подтверждению ставит релиз 0.3.0 (zip скачивается с GitHub со сверкой SHA-256 или выбирается с диска, на сервер по SFTP уходят только `install.sh` и бинарник нужной архитектуры; curl/unzip на сервере не нужны). Установка не включает firewall.
- Включает веб-службу VPSWall (`127.0.0.1:8090` на сервере), выдаёт токен с `SSH_CONNECTION` текущей сессии и поднимает эфемерный туннель. Вид «Порты»: правила VPSWall, «Открыть/Закрыть порт», «Открыть сейчас на N минут/часов», пауза и удаление окон. «Полная панель» открывает веб-интерфейс VPSWall в отдельном окне с подставленным токеном (отдельная непостоянная сессия, переходы за пределы панели запрещены).
- Изменения идут только через API VPSWall с его откатом через 120 с. Кнопка «Подтвердить из нового SSH» открывает новое подключение с параметрами сессии (на новый SSH-порт, если он меняется) и выполняет `vpswall confirm`.
- Права root: под root — напрямую, иначе `sudo -n`; если sudo просит пароль, LiteSSH спрашивает его и передаёт через stdin (`sudo -S`). Пароль и токен держатся только в памяти до закрытия вкладки, в командную строку и журналы не попадают. Туннель снимается вместе с вкладкой; веб-служба остаётся включённой — кнопка «Отключить веб-службу» делает `vpswall web disable`.
- `npm run test:ssh`: sudo с паролем (и неверным), выдача токена, API панели через туннель с проверкой Origin, confirm из нового подключения; с `VPSWALL_DEMO_PORT=8091` — против настоящего `vpswall web --demo`, включая окно панели.

## 1.1.10 — 2026-11-17

### Подключение через другое соединение (ssh -J) и порт SSH

- В форме сессии поле «Подключаться через (бастион / ProxyJump, как ssh -J)»: выбирается сохранённая сессия-бастион. Бастион задаётся в самой сессии, туннель его не добавляет. В списке у бастиона виден нестандартный порт; под полем — подсказка, куда именно откроется канал (хост и порт целевого сервера так, как их видит бастион).
- Поле «Порт SSH» подписано явно, ограничено 1–65535: для сервера, где sshd перенесён со стандартного 22 (например на 2222), порт нужно поменять в сессии.

### Туннели

- Отказ отдельного соединения через работающий туннель (бастион или сервер не открыл канал, цель недоступна, `AllowTcpForwarding no`, у `-R` локальный порт закрыт) раньше был невидим: сокет просто закрывался, а туннель горел зелёным. Теперь причина показывается в строке туннеля («Соединение не открылось: хост:порт — …»), ошибка запуска (порт занят) — текстом, а не только во всплывающей подсказке.
- Ошибка сохранения туннеля (неверный порт и т.п.) показывается уведомлением, а не теряется молча.

### Проверки

- `npm run test:ssh`: терминал на сервере с нестандартным портом через отдельный бастион со своими учётными данными, туннель `-L` поверх такой сессии, видимость отказа канала.

## 1.1.8 — 2026-11-14

### Платформа

- Electron 33 → **45.3.2**: Electron 33 больше не получал исправлений безопасности Chromium и Node.js.
- better-sqlite3 11 → **13.1.1**: модуль на N-API с готовыми бинарниками в пакете — больше не нужен prebuild-install под конкретную версию Electron.
- MCP SDK (`@modelcontextprotocol/server` 2.4.0, `@modelcontextprotocol/node` 2.1.2), `zod` 4.6.7, `hono`: закрыты уязвимости HIGH — исчерпание памяти при валидации запроса, неограниченные пакеты JSON-RPC. `npm audit` по runtime-зависимостям — 0 уязвимостей.

### Утечки и падения

- Перезагрузка или падение окна закрывает его SSH-сессии, локальные терминалы и туннели — раньше они оставались висеть невидимыми до выхода из приложения. Подключение, завершившееся уже после перезагрузки, тоже закрывается.
- В установленной версии убрано скрытое стандартное меню Electron (Windows/Linux): Ctrl+R вне терминала перезагружал окно со всеми вкладками, Ctrl+W прятал его, Ctrl+Shift+I открывал DevTools.
- Туннели `-L`/`-D`: если клиент обрывал соединение, пока открывался канал, SSH-канал оставался открытым навсегда (через SOCKS браузеры делают так постоянно).
- Ошибка shell-канала, SFTP-канала или сброс соединения RDP-клиентом больше не роняют приложение со всеми сессиями.
- Одновременные первые обращения к SFTP (например, параллельные вызовы MCP) больше не открывают лишний канал.
- Предпросмотр `/dev/zero` и подобных файлов больше не читает бесконечно до нехватки памяти — показывается только для обычных файлов.

### Безопасность

- Скачивание с сервера отклоняет имена файлов вроде `..\..\evil.exe` — злонамеренный сервер не может записать файл вне выбранной папки (класс CVE-2019-6111 / CVE-2018-20684). На Windows отклоняется и `:` (альтернативный поток NTFS).
- Вставка в терминал удаляет маркеры bracketed paste из текста — строка из буфера обмена больше не может выполниться сразу после вставки; заодно исключена двойная вставка по Ctrl+V.
- Скрипт «загрузить и выполнить» создаётся в `/tmp` с правами 0600, а не читаемым для всех пользователей сервера; экспортированный приватный ключ — тоже 0600.
- При входе по ключу или агенту не отправляются пустые ответы keyboard-interactive — они считались неудачными попытками входа (MaxAuthTries, fail2ban).
- Ключ мастер-пароля затирается в памяти при блокировке.

### Исправления

- Установка ключа на сервер больше не портит `authorized_keys`, если файл не кончался переводом строки (новый ключ склеивался с последним).
- Удаление сессии удаляет и её туннели; у сессии, чей бастион удалён, понятная ошибка вместо «Сессия не найдена».
- Терминал больше не остаётся чёрным после потери WebGL-контекста (сон, сброс GPU, больше ~16 терминалов) — переключается на обычный рендер.

### Обслуживание

- `npm run test:ssh`: +4 проверки — очистка ресурсов окна, гонка подключения с перезагрузкой, удаление туннелей вместе с сессией, фильтр небезопасных имён файлов.
- CI собирает на Node.js 22 (требование better-sqlite3 13).

## 1.1.7 — 2026-09-29

### Git

- Проверка ссылки на репозиторий кнопкой рядом с полем (и в «Проверить») — без выбора папки: найден ли репозиторий, пустой ли, есть ли доступ, какие ветки, будет ли создана ветка.
- Для несуществующего репозитория показывается понятная причина и кнопка «Создать репозиторий» (GitHub, GitLab, Bitbucket).
- Поддержаны не только GitHub, но и GitLab, Gitea, Bitbucket и собственные серверы (https и SSH); транспорт `ext::`, локальные пути и токены в ссылке отклоняются.
- Git запускается без интерактивных запросов логина — операции больше не «зависают» молча до таймаута.
- Публикация сначала проверяет удалённый репозиторий и не создаёт коммит/origin в папке, если он недоступен.
- Введённая ссылка больше не перетирается значением origin при проверке папки.

### Подключение и терминал

- Таймаут подключения не идёт, пока открыт диалог ключа хоста — соединение больше не обрывается, если отпечаток проверяют дольше 20 секунд.
- Баннер и первое приглашение сервера (и локального терминала) больше не теряются: вывод копится до монтирования терминала.
- В историю команд не попадает то, что вводится после запроса пароля (sudo, ssh, gpg…), и строки с ведущим пробелом.
- Вставка использует bracketed paste: многострочный текст не выполняется сразу и при синхронном вводе уходит во все панели.
- Смена типа ключа сервера (например, rsa → ed25519) показывается как предупреждение о смене ключа, а не как новый хост.
- Установка ключа на сервер работает через бастион (ProxyJump).
- Соединение, закрытое сервером без ошибки, завершает попытку сразу, а не по таймауту.
- Метрики не запускают новый замер, пока не пришёл предыдущий; у команд есть таймаут — каналы SSH больше не забиваются.
- Журнал сессии не рвёт многобайтные символы UTF-8.

### Туннели

- SOCKS5 (`-D`): данные, отправленные сразу после запроса, больше не теряются; «успех» отправляется только после открытия канала, при отказе клиент получает код ошибки.
- Туннель с ошибкой (например, занятый порт) перезапускается повторным запуском.
- Split view: при закрытии главной панели туннели, SFTP-очередь и MCP-мост переходят к оставшейся панели, а не отключаются.

### Файлы (SFTP)

- Если размер файла на сервере прочитать не удалось, скачивание завершается ошибкой, а не пустым файлом с отметкой «готово».
- При скачивании папки символические ссылки раскрываются (с защитой от циклов), битые пропускаются.

### MCP

- Запись через «битую» символическую ссылку внутри корня запрещена — она могла вести за пределы разрешённой области.
- Остановка моста больше не зависает на открытых соединениях клиента.
- Сервер сообщает клиентам актуальную версию приложения.

### Хранилище и сессии

- Включение и отключение мастер-пароля выполняется одной транзакцией; при сбое режим откатывается, секреты не становятся нерасшифровываемыми.
- Импорт `~/.ssh/config`: поддержаны `Include`, `ProxyJump`, форма `ключ=значение`, пути в кавычках; блоки `Match` больше не прилипают к предыдущему хосту; повторный импорт не создаёт дубли.
- Экспорт/импорт JSON сохраняет бастион, проброс агента и теги; повторный импорт не создаёт дубли.

### Оформление

- Активная вкладка читаема в светлой теме.
- Предупреждения и статусы в диалогах MCP и Git читаемы в светлой теме.
- Второстепенный текст стал контрастнее в обеих темах.
- Редактор кода, просмотрщик и редактор скриптов следуют теме приложения.
- Кнопка «Переподключить» больше не перекрывает панель поиска в терминале.
- Диалог Git использует общий слой окон — подтверждения не прячутся под ним.

### Обслуживание

- Добавлен интеграционный тест `npm run test:ssh`: локальный SSH-сервер под Electron проверяет ожидание ключа хоста, буфер вывода, SOCKS, перезапуск туннелей, split, бастион, импорт сессий.
