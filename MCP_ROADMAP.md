# План развития MCP-доступа

## Реализовано в 1.1.4

- Живая панель активности рядом с терминалом: сервер, клиент, инструмент, состояние, длительность, поиск и фильтры.
- Детали вызова: параметры без содержимого файлов; для `ssh_exec` — команда и ограниченный предпросмотр `stdout`/`stderr` только в памяти и только после раскрытия пользователем.
- Отдельные токены для Codex, Claude Code и других клиентов внутри каждого MCP-моста.
- Журнал `%APPDATA%\LiteSSH\logs\mcp-YYYY-MM-DD.jsonl`: переходы «начало/завершение», ротация по 5 МиБ, хранение до 14 дней, экспорт итоговых записей JSONL с фильтрами. Команды и вывод в журнал и экспорт не попадают.

## Позже: контроль выполнения (пункт 4)

- Остановка конкретного выполняющегося `ssh_exec` без закрытия других MCP-вызовов.
- Временная блокировка операций записи и команд для выбранного моста, с индикацией в UI и отказом на сервере.
- Отзыв отдельного клиентского токена без прерывания других клиентов.
- Явное подтверждение удаления, перезаписи и потенциально опасных команд перед исполнением.

Критерий готовности: отмена одного вызова не затрагивает другие; закрытый доступ перестаёт принимать запросы немедленно; отказ/разрешение отражаются в журнале.

## Позже: защита изменений файлов (пункт 5)

- Предпросмотр diff перед заменой текстового файла через MCP.
- Восстановимая резервная копия исходного файла с лимитом размера и срока хранения.
- Для бинарных файлов — сравнение размера и хеша вместо текстового diff.

Критерий готовности: пользователь видит точный целевой путь и изменение до подтверждения; после отказа файл не меняется; после разрешения доступно восстановление.
