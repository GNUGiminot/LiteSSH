# Анализ исходного промпта LiteSSH

Взгляд сетевого инженера и разработчика: что в ТЗ хорошо, что противоречиво, и что я предлагаю изменить до начала работы.

## Что в промпте хорошо

- Чёткий фокус: «MobaXterm, но легче и красивее» — понятная ниша, MobaXterm действительно перегружен и Windows-only.
- Правильный набор ядра: терминал + SFTP + менеджер ключей + туннели. Это 95% ежедневной работы с серверами.
- Реалистичная приоритизация по версиям (MVP → v2.0).
- Внимание к безопасности хранилища (AES-256-GCM, мастер-пароль, keychain).

## Главное противоречие ТЗ

> «Легкий клиент, запуск < 2 сек, RAM < 200MB, плавно на 4GB RAM»
> при стеке **Electron + React + Monaco + PDF-рендерер**

Пустое Electron-приложение — это уже ~150–250MB RAM (несколько процессов Chromium). Добавив Monaco, pdf.js и React-дерево с 10000+ файлов, в 200MB не уложиться. Есть два честных пути:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Tauri 2 + Rust (russh) + React** | 30–80MB RAM, старт <1 сек, реальный «lite» | SSH-стек на Rust менее «батарейный», чем ssh2; дольше MVP |
| **Electron, но с бюджетом ресурсов** | ssh2/node-pty/xterm.js — зрелая экосистема, быстрый MVP | Цель по RAM надо честно поднять до ~300–400MB |

**Моя рекомендация: остаться на Electron** — для личного инструмента скорость разработки и зрелость ssh2 важнее 200MB в машине с 32GB. Но заложить дисциплину: lazy-load тяжёлых модулей (Monaco, pdf.js грузятся только при первом использовании), виртуализация списков, один renderer-процесс на окно. Целевые метрики скорректировать: старт < 3 сек, RAM < 350MB без сессий. Если позже захочется по-настоящему «lite» — архитектура с изолированным ssh-core позволит портироваться на Tauri.

## Что я добавляю в стек (в ТЗ пропущено)

- **xterm.js** — в ТЗ вообще не назван эмулятор терминала, а это сердце приложения. xterm.js + аддоны (fit, search, webgl, unicode11) — безальтернативный стандарт.
- **node-pty** — для локальных терминалов (bonus-фича, в MobaXterm она ключевая).
- **electron-vite** — сборка main/preload/renderer, HMR.
- **Zustand** — состояние renderer'а (Redux избыточен).
- **TanStack Virtual** — виртуализация файловых списков (иначе 10000+ файлов убьют DOM).
- **zod** — валидация конфигов при импорте/экспорте и IPC-границе.

## Что я изменяю в требованиях

1. **Хранение паролей**: по умолчанию — **системный keychain** (Windows Credential Manager / macOS Keychain / libsecret) через `safeStorage` Electron, а мастер-пароль + AES-256-GCM — опциональный режим для переносимого профиля. В ТЗ приоритет обратный; keychain безопаснее и не раздражает вводом мастер-пароля при каждом запуске.
2. **2FA для доступа к приложению** — убираю. Локальное десктоп-приложение защищается сессией ОС + keychain; своя 2FA — театр безопасности и трение. Оставляю автоблокировку хранилища по неактивности.
3. **PDF-рендер и просмотр архивов** — переношу из v1.5 в «после v2.0». Редко нужны, тяжёлые. Текст (Monaco), изображения и hex-viewer покрывают 99% случаев.
4. **Многооконность с группировкой по проектам** — упрощаю до «несколько окон + вкладки внутри окна». Группировка окон по проектам — сложная фича с сомнительной ценностью для личного инструмента.
5. **Планировщик задач в макросах** — убираю из v2.0 (для этого есть cron на серверах). Оставляю сниппеты и запись/воспроизведение команд.
6. **Двухпанельный SFTP** — делаю основной режим «локальная панель ↔ удалённая панель» (как в MobaXterm side-panel это неудобно; двухпанельник — то, за что любят WinSCP/Total Commander).
7. **known_hosts и верификация host key** — в ТЗ отсутствует вообще, а это критично для SSH-клиента: проверка отпечатка при первом подключении, предупреждение при смене ключа сервера (защита от MITM).
8. **Jump hosts / ProxyJump** — в ТЗ нет, добавляю в v2.0: для сетевого инженера подключение через бастион — ежедневная необходимость.
9. **Импорт из ~/.ssh/config и PuTTY** — добавляю к импорту/экспорту: миграция существующих хостов — первое, что нужно при переезде на новый клиент.
10. **Секция «Структура проекта» в ТЗ битая** (просто цифры 1–14) — полная структура описана в ARCHITECTURE.md.

## Скорректированные критерии успеха

- Холодный старт < 3 сек, тёплый < 1.5 сек
- RAM < 350MB без активных сессий (Monaco/pdf не загружены)
- Открытие каталога с 10 000 файлов по SFTP < 2 сек, скролл без лагов (виртуализация)
- Латентность ввода в терминале неотличима от PuTTY (WebGL-рендерер xterm.js)
- Ни один секрет не пишется на диск в открытом виде; host key verification включена всегда
