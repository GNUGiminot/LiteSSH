# Архитектура LiteSSH 1.1.6

Документ описывает фактическое состояние исходников версии 1.1.6. Идеи, которые ещё не реализованы,
перечислены отдельно в `PLAN.md` и `MCP_ROADMAP.md`.

## Технологический стек

| Слой | Технология |
|---|---|
| Оболочка | Electron 33, electron-vite, electron-builder |
| Интерфейс | React 18, TypeScript, Tailwind CSS 3, Radix UI, Lucide |
| Терминал | xterm.js: fit, search, web-links, WebGL |
| SSH/SFTP | ssh2 в main-процессе |
| Локальный терминал | node-pty |
| Хранилище | better-sqlite3 |
| Секреты | Electron safeStorage либо мастер-пароль: scrypt + AES-256-GCM |
| Состояние UI | Zustand |
| Редактор | CodeMirror 6, загружается лениво |
| IPC-валидация | zod |
| MCP | Streamable HTTP на loopback через `@modelcontextprotocol/server` |

## Границы процессов

SSH-клиенты, SFTP, локальные PTY, база данных, секреты и MCP-мосты находятся в main-процессе.
Renderer не получает прямой доступ к Node.js: включены `contextIsolation`, `sandbox`, выключен
`nodeIntegration`. Разрешённые операции передаются через preload и типизированный IPC.

```text
Renderer (React)
  App / TerminalView / FileManager / TransferQueue / MCP panels
                     │ typed IPC
Preload              │ window.api
                     ▼
Main process
  ipc.ts
    ├─ connection-manager.ts ─ SSH shell / exec / SFTP channels
    ├─ sftp-manager.ts       ─ transfers and per-session FIFO queues
    ├─ tunnel-manager.ts     ─ local / remote / SOCKS tunnels
    ├─ mcp-bridge.ts         ─ per-session loopback MCP endpoints
    ├─ mcp-activity.ts       ─ metadata audit log and export
    ├─ local-fs.ts / pty-manager.ts
    ├─ vault.ts / keys.ts / host-keys.ts
    └─ db.ts
```

## Передача файлов

- Для каждого SSH-сеанса действует отдельная последовательная FIFO-очередь. Разные сеансы могут
  передавать данные параллельно.
- Для каждого задания открывается отдельный SFTP-канал, поэтому листинг и другие задания не делят
  один поток передачи.
- Папка сначала сканируется, после чего файлы передаются по очереди с прогрессом по файлам и байтам.
- Незавершённый файл хранится как `<имя>.litessh-part`. Обычная новая передача начинает файл заново;
  продолжение по смещению выполняется только по явной команде resume.
- После завершения проверяется размер, затем временный файл атомарно заменяет целевой.
- Очередь и состояние видны в `TransferQueue`; для локального результата доступно открытие в Проводнике.

## MCP-доступ

- Каждая активная SSH-сессия может иметь собственный MCP-мост с отдельным loopback-портом,
  разрешённым серверным корнем и набором прав.
- Для Codex, Claude Code и универсального клиента выдаются отдельные Bearer-токены.
- Закрытие SSH-сессии отзывает только связанный с ней мост.
- Панель активности получает события в реальном времени. На диск записываются только метаданные;
  команды и содержимое файлов в постоянный журнал не входят.
- Журнал хранится в `%APPDATA%\LiteSSH\logs`, ротируется и очищается по сроку хранения.

Отложенные средства подтверждения опасных операций, отмены команды и diff/backup описаны в
`MCP_ROADMAP.md`.

## Публикация на GitHub

- Мастер принимает локальную папку либо путь текущей SSH-сессии и существующую ссылку GitHub.
- Локальный режим запускает установленный Git; авторизация выполняется через Git Credential Manager.
- Серверный режим выполняет Git внутри уже открытого SSH-соединения и не передаёт серверу локальные токены.
- Перед отправкой показываются изменения и возможные секреты, `.gitignore` дополняется без перезаписи.
- Синхронизация допускает только fast-forward. Force push и автоматическое объединение расходящихся
  историй запрещены.

## Хранилище и безопасность

SQLite хранит сессии, группы, known_hosts, туннели, сниппеты, историю, скрипты, ключи и метаданные
vault. Пароли и приватные ключи сохраняются только в зашифрованном виде. Проверка host key выполняется
до доверия соединению; смена известного ключа требует решения пользователя.

MCP слушает только `127.0.0.1`, требует Bearer-токен и дополнительно ограничивает файловые операции
выданным серверным корнем, включая проверку символических ссылок.

## Не реализовано или отложено

- Виртуализация очень больших файловых списков.
- Автоматическое переподключение без действия пользователя.
- Drag-out удалённых файлов в ОС.
- Подтверждение и отмена отдельных MCP-операций, diff и восстановимые MCP-бэкапы.
- Сборки Linux/macOS и фактическая подпись Windows-установщика сертификатом владельца.
